# 自然语言驱动 2D→3D：AI 参与全流程实录与尺寸来源说明

> 本文件回答两个问题：
> 1. 仓库里那些"参数化脚本"是怎么由**一句自然语言**驱动出来的（AI 实际参与了什么）？
> 2. CAD 图纸案例中，哪些尺寸来自图纸、哪些是人工补充或 AI 默认？

## 1. 一句话 → 3D 的完整闭环

```
用户一句话 + 二维素材
   │
   ▼
[AI-1 理解]  意图识别：要建什么对象（壳体/液压缸/包装盒…）
   │          对象无法从图纸自动读图 → 用自然语言问答补齐几何语义
   ▼
[AI-2 结构化] 输出参数 JSON：对象类型 + 尺寸 + 特征（孔/法兰/杆…）
   │          标注每个尺寸的来源：图纸 / 用户补充 / AI 默认
   ▼
[AI-3 编码]   生成或修改 Blender Python 脚本（bpy/bmesh/布尔…）
   │          运行时错误 → traceback 回填 → 迭代修复
   ▼
[执行]       blender --background 自动建模 → 导出 .glb/.blend
   │
   ▼
[出图]       render_glb.py 自动取景渲染多视角 PNG
   │
   ▼
[人工核对]   用户用 Blender 打开查看 → 说"改哪里" → 回到 AI-2 迭代
```

对应代码：`scripts/nl_to_3d.py`（NL→JSON→Blender 演示），建模脚本见 `scripts/build_*.py`。

## 2. 真实案例实录（保留实际对话决策过程）

### 案例 1 · 液压缸（P4，主案例）
| 环节 | 内容（真实过程） |
|---|---|
| 用户输入 | 二维图纸 `cad2_kAmpQGMUEd7t9Zok.jpg` + "机械零件 液压缸" |
| AI 判断 | 无法自动读取 CAD 标注 → **几何语义需人工/一句话补充**，这正是考题"一句话驱动"的入口 |
| AI 决策链 | ① 对象=液压缸（回转体+杆+法兰）→ ② 采用典型默认参数 → ③ 写 `build_hydraulic.py` |
| 编码与修复 | 运行时报错 `transform.rotate` 参数变化 → 改用 `rotation_euler`；导出时混入地面 → 排除地面；**单位 mm 误当 m（放大1000倍）→ 修复 mm→m 换算** |
| 结果 | `hydraulic.glb` / `hydraulic_view.blend` / 3 视角 PNG；用户 Blender 核对 |

可复现的一句话示例（`nl_to_3d.py`）：
```
生成液压缸：缸筒外径80mm 长260mm，法兰Ø110，活塞杆Ø28 伸出250
```

### 案例 2 · 阶梯回转壳体（P3）
| 环节 | 内容 |
|---|---|
| 用户输入 | CAD 工程图 `cad_8191871.jpg` + "机械零件 带尺寸工程图 A" |
| AI 追问 | 因无法读标注，以"一句话"收集形状 → 用户："壳体"→ 选项 →"3 阶梯回转壳体" |
| AI 参数 | 法兰 Ø110×8 + 4×Ø8 孔、主体 Ø80×50、凸台 Ø40×8 + 中心 Ø20 通孔、内腔 Ø68，总高 66（默认） |
| 结果 | 用户 Blender 核对 → OK |

### 案例 3 · 包装盒（P1，最小原型）
| 环节 | 内容 |
|---|---|
| 用户输入 | `front.png` 正面图 + "做成 180×45×45mm 的盒子"（等价一句话） |
| AI 参数 | width=180 / depth=45 / height=45 mm（`build_pack.py` 参数即 NL 输出的槽位） |

## 3. CAD 图纸尺寸来源标注（诚实说明）

当前流程**未集成 CAD 标注自动读取**（无 OCR/图纸解析），因此尺寸来源分三类：

| 案例 | 尺寸项 | 来源 | 说明 |
|---|---|---|---|
| P4 液压缸 | 缸筒 Ø80×260、法兰 Ø110、杆 Ø28 伸 250、油口 Ø30 | **AI 默认假设** | 依据"典型液压缸"比例给出；用户未提供图纸读数 |
| P4 液压缸 | 对象类型=液压缸 | **来自一句话**（用户口述） | 非图纸自动识别 |
| P3 壳体 | 法兰/主体/凸台/孔/内腔 | **AI 默认假设** | 依据"阶梯回转电机/泵壳"典型结构 |
| P3 壳体 | 类型=阶梯回转壳体 | **来自一句话**（用户选择"3"） | 非图纸自动识别 |
| P1 包装盒 | 180×45×45 mm | **来自一句话/默认** | NL 可直接改（见 demo） |
| 全部 | 轮廓/线型/几何比例 | 图纸（人工目视参考） | 几何语义靠人/AI 从图判断，未像素级读取标注 |

> 结论与局限：**"从图纸自动读尺寸"是当前方案未实现、也是最重要的待验证假设之一**。
> 未来接入 CAD 标注 OCR / 视觉 LLM 后，可将 `from_drawing` 列为真实来源；
> 在此之前所有 CAD 案例的几何参数均视为 **AI 默认 + 一句话补充**，需用户按图纸核对（这正是使用说明 G 节"局限 2/3"的实证）。

## 4. 可复现演示

```powershell
python scripts/nl_to_3d.py --text "做一个包装盒 180x45x45 mm" --blender "<blender路径>"
python scripts/nl_to_3d.py --text "液压缸 缸筒外径80 长260" --blender "<blender路径>"
python scripts/nl_to_3d.py --text "壳体" --demo-only      # 只输出解析 JSON，不调用 Blender
```

- 解析器为**离线可复现规则**（演示用）；真实理解由大语言模型完成，见上文实录；
- 每步会输出结构化 JSON（含 `dimension_source` 来源标注）到 `output/nl_*.json`。
