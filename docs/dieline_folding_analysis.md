# 刀模图自动折叠失败原因分析

> 本文如实总结本项目在"刀模图 → 3D 折叠"上反复失败的原因、技术本质与最终可行方案。
> 记录时间：2026-09-15

## 一、结论（先看这里）

**失败不是因为"少写了几行代码"，而是三个层面的问题叠加：**

1. **信息层面**：展开图本身**不含折叠所需的关键信息**（折向、折角、折叠顺序）；
2. **语义层面**：位图/复杂矢量图里**无法区分"折线"与"标注线、图案线、尺寸数字"**；
3. **算法层面**：把平面按折线折起来属于**刚性折纸（rigid origami）约束求解**，不是简单的几何变换。

最终能做出正确模型，靠的是**拿到了 Pacdora 的官方结构数据**（盒型 + 精确尺寸 + 面片轮廓），而不是"从图上猜折叠"。

---

## 二、根本原因：展开图缺少折叠语义

一张 2D 展开图 = 3D 折叠体摊平的结果。**从平面反推 3D 是病态问题（ill-posed）**：

| 折叠必需的信息 | 展开图是否提供 |
|---|---|
| 切线（裁切轮廓） | ✅ 有（实线 / 特定颜色） |
| 折线位置 | ✅ 有（虚线 / 分组 / 颜色） |
| **折向（山折 / 谷折）** | ❌ **没有** |
| **折叠角度（90° / 180° / 其它）** | ❌ **没有** |
| **折叠顺序与层级依赖** | ❌ **没有** |
| 哪个面是底、哪个是盖 | ❌ 需要盒型知识 |
| 提手的对折关系 | ❌ 需要结构知识 |

**同一张展开图可以对应多种折叠结果**（例如都折 90°，但折向不同 → 一个成盒、一个外翻）。缺少折向时，任何折叠都是"猜"。

---

## 三、技术难点：这是约束求解问题，不是几何变换

即使折向已知，"把平面按折线折起来"在数学上是**刚体折纸**问题：

| 约束 | 说明 |
|---|---|
| 面片刚性 | 每个面不能拉伸/弯曲 |
| 折线闭合 | 折线两侧的面必须对齐、边要重合 |
| 拓扑成环 | 盒壁四面互连（不是树），简单 BFS 无法求解 |
| 无自交 | 折叠后不能穿插（需碰撞检测） |
| 顺序依赖 | 有些面必须先折，才能折下一个（如自锁底） |

本项目用"BFS + 层级奇偶折向 / 按折线方向定折向"做近似，**必然得不到正确盒形**——实测：
- 统一折向 → 面板外翻或重叠；
- 4 种折向组合穷举 → 包围盒 X 恒为 348mm（说明垂直折叠轴本身有问题）；
- 提取到 15 个面板但只有 11 对折线邻接（面提取与邻接匹配不完整）。

## 四、本项目具体失败案例（时间线，如实记录）

| # | 素材 | 我的做法 | 失败原因 |
|---|---|---|---|
| 1 | `material_fw658.webp` | 当刀模图解析 | **它其实是白底设计稿**（86.7% 白色背景 + 图案），不是刀模 |
| 2 | `dieline_2018.jpg` | 检测"红色虚线"当折线 | 红色里混有 **638 个尺寸数字小块**、图案线条；折线候选 16+13 条（远超盒型应有的 4-7 条）|
| 3 | 同上 | 按"均匀分布"猜 3 条垂直折线 | 用户指出"中间四壁折线识别错误"；真实折线位置靠猜不可靠 |
| 4 | `templatemaker_giftbox.svg` | 用 fold/cut 分组 + 平面细分 + 折叠 | 折出 12 个面，但**折向靠"层级奇偶"猜** → 形状错乱，用户反馈"完全错误" |
| 5 | Pacdora SVG | 用精确红线坐标折叠 | 仍缺折叠顺序；**4 种折向组合都不成盒**（X 恒 348mm）|
| 6 | Pacdora 官方数据 | 拿到 18 个面片轮廓 | 提手初次做成"方框 + 顶梁"（自己猜的形状），用户指出"**上部不对**"|

**共同失败点**：我一直在"**从图形推断折叠**"，而这一步本质上信息不足。

## 五、工业界的正确做法

| 软件 | 做法 |
|---|---|
| Pacdora / Esko ArtiosCAD / Packmage | **盒型模板库 + 参数化折叠引擎**：每个盒型（如"自锁底手提箱"）有专门的折叠算法代码；刀模图只用于开刀模/印刷 |
| Pacdora 的实现 | 前端用 `knife2gltf.min.wasm`（**盒型专用折叠引擎**）把刀模数据转成 glTF；折叠逻辑在 WASM 内，**数据里不含折向参数** |
| 学术界（PackFold 等） | 限制在**特定盒型 + 简单折向**，且通常需要额外标注 |

**没有任何工业软件做"从任意展开图自动推断折叠"** —— 这正是我走过的弯路。

## 六、最终可行的方案（本项目已实现）

### 关键突破：拿到官方结构数据

从 Pacdora 分享页逆出数据接口：

```
GET https://www.pacdora.cn/api/v2/project/share/view?filter_url=<id>&type=project
```

返回内容：
- **盒型**：`自锁底手提箱`（code: `BotselflockSuitcase`，分类号 112320）
- **精确尺寸**：`knife.size` = L153 × W150 × H180 mm
- **18 个面片**：每个含 `name / w / h / x / y / dlist[]`（路径点，含圆弧 A 命令）
  - 四壁：H / FR / F / FL
  - 提手：HT1+HT2（竖直段+弧顶）、FT1+FT2
  - 提手孔：`x`（52×30）
  - 自锁底：HB / FB / HBR / FBR / FRB / FLB（带斜角的互锁形状）
  - 糊口：HL

### 实现脚本

| 脚本 | 作用 |
|---|---|
| `scripts/mvp/pacdora_handbag.py` | 按折线坐标折叠（失败尝试，保留作对照）|
| `scripts/mvp/handbag_from_data.py` | 按官方尺寸生成手提箱主体 |
| `scripts/mvp/handbag_lock_bottom.py` | **还原自锁底互锁结构**（6 底片精确轮廓 + 三层搭接）|
| `scripts/mvp/handbag_full.py` | **完整版**：四壁 + 互锁底 + 侧顶 + 提手（弧顶）+ 提手孔 |

### 成果验证

```
X = 153 mm（箱长）✅
Y = 150 mm（箱宽）✅
Z = 255 mm = 180（箱高）+ 75（提手）✅
```

## 七、经验教训

1. **先确认信息边界**：对结构化工业图纸，先判断"这是矢量还是位图""有没有折叠标注""能否拿到结构数据"，再决定技术路线——不要一上来就写算法试错；
2. **折叠的关键是语义，不是几何**：折线位置容易提取，**折向/顺序/角度**才是决定成败的信息；
3. **工业标准做法是模板 + 参数**：用可靠的盒型模板（配参数）实现"可靠交付"，而不是追求"任意图自动折叠"；
4. **能拿数据就不要猜图像**：矢量/接口数据（SVG 分组、官方 JSON）比像素推断可靠得多；
5. **本项目产品方案 M4 的方向是对的**（"参数化结构模板"），我一度偏离去做"通用自动折叠"，导致反复失败。

---

## 八、后续可改进方向

1. **接入盒型折叠规则库**：每个盒型（RTE / 自锁底 / 天地盖）配一套折叠规则（折线 → 折向 + 角度 + 顺序），从"推断"变为"查表"；
2. **接入刚性折纸求解器**：若要做通用折叠，需要约束求解 + 碰撞检测；
3. **优先支持矢量 + 结构化数据**：SVG（含 fold/cut 分组）、官方数据接口、DXF 图层；
4. **提手/互锁等复杂结构**：用精确轮廓（dlist 路径点）建模，而非矩形简化。
