# 分析报告（analysis.md）—— 考题四技术向

## 1. 摘要

二维设计稿 → 三维展示模型的自动化难点集中在「几何正确性」与「贴图对齐」两处，
恰好是通用 LLM 直接生成 Blender 脚本最不稳的部分。本方案采用
**参数化模板兜底几何与 UV、LLM 承担意图理解与局部脚本修改、执行错误回填 + 渲染自检闭环** 的技术路线，
并以「长方体包装盒 + 单张正面设计图」作为最小原型验证。

## 2. 核心流程梳理

输入（2D 素材 + 参数/自然语言）→ ① 输入解析 → ② 结构建模 → ③ UV 与贴图 →
④ 材质 → ⑤ 渲染与导出（PNG / glTF）。

| 环节 | 关键问题 | 本方案做法 |
|---|---|---|
| 建模 | 几何正确性、尺寸比例 | 参数化模板（宽/深/高），不依赖 LLM 造点 |
| 贴图 | UV 与素材布局对齐、文字方向 | 分面独立贴图，front 固定 +Y 面向镜头 |
| 材质 | 节点图复杂、风格词→数值映射 | Principled BSDF + 图像纹理；粗糙度预设 |
| 渲染 | 布光/机位/引擎 | 棚拍背景 + 区域光 + EEVEE 迭代 / Cycles 出图 |

## 3. 现状调研：LLM 辅助 Blender 自动化

| 方案 | 类型 | 能力 | 局限 |
|---|---|---|---|
| BlenderGPT（2023） | 单轮 NL→脚本 | 基元建模 | 无上下文、无排错 |
| Blender Copilot / 3D Moder Copilot | 会话插件 | 建模/渲染指令 | 缺工程化校验 |
| LL3M（2025, arXiv:2508.08228） | 多智能体+RAG+自反思 | 复杂资产、可迭代 | 系统重、成本高 |
| Blender MCP | 工具协议层 | 结构化可控 | 需常驻服务 |
| CodeGen-3D 基准 | 评测 | 量化成功率 | 合成任务 |

关键证据：CodeGen-3D 实测通用 LLM 直接生成脚本失败率 21%–92%，
专用 + 迭代自纠错系统失败率 3%–4%；LL3M 表明「代码 + 渲染图双路自检 + API 检索」显著提成功率。
结论：**不赌单次生成，模板兜底 + 反馈闭环**。

## 4. 难点分析与方案设计依据

| 维度 | 难点 | 根因 | 对策（设计依据） |
|---|---|---|---|
| 建模 | bpy.ops 依赖上下文 | 需活动对象/选择集，无头易崩 | 数据层 API + 模板封装 |
| 建模 | 坐标/比例推理弱 | LLM 数值心算不可靠 | 尺寸走结构化参数 |
| 建模 | API 版本漂移 | 输出旧版参数 | 锁定版本 + RAG 注入文档 |
| 贴图 | UV 与素材难对齐 | 展开图布局理解难 | 固定 UV 布局规范 |
| 贴图 | 文字镜像/倒置 | 图像 v 轴方向 | 渲染后目检 + 素材规范 |
| 材质 | 节点图复杂 | 图结构文本化易漏连 | 少量节点 + 封装函数 |
| 材质 | 风格词→数值 | 映射不稳定 | 风格预设字典 |
| 渲染 | 无头无视觉反馈 | 看不到结果 | 自动出缩略图回看 |
| 渲染 | 布光参数玄学 | 经验性强 | 固定产品展示灯光模板 |

## 5. 方案设计

架构：交互层（一句话 + 上传素材）→ 理解层（LLM 抽取 JSON 槽位）→ 生成层（模板优先 + LLM 局部修改 + RAG）
→ 执行层（Blender headless 沙箱）→ 校验闭环（traceback 回填 ≤3 次、渲染图目检、几何校验）→ 输出层（PNG/glTF）。

设计原则：模板兜底几何、结构化中间表示、执行反馈闭环、知识检索、脚本化可复现。

典型交互：用户上传 front.png 说「做成 180x45x45mm 牙膏盒，磨砂覆膜」→
系统输出 JSON 槽位 → 模板生成脚本 → 无头执行 → 返回三机位渲染图；追加修改时复用上下文只改局部脚本。

## 6. 最小原型与实验结果

选型：长方体包装盒（几何可参数化、素材易得、最能体现 2D→3D）。
贴图：六面独立贴图，front 必填，其余纯色兜底。渲染：EEVEE/Cycles + 棚拍布光。

## 7. 结论与展望

- 可靠路线 = 模板承接几何与 UV，LLM 承接意图与脚本修改，反馈闭环降失败率。
- v2 展望：展开图整贴六面（UV 坐标表统一）、dieline 自动折叠、VLM 自动目检、多对象场景。
