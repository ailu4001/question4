## 2. AI 设计决策（真实推理过程）

| 决策点 | 分析 | 结论 |
|---|---|---|
| 修改方式 | 选项A：重建参数化模板（全部尺寸经 JSON 传入，几何相对布局）——最灵活但需重构几何、回归验证成本高；选项B：**常量级替换生成脚本副本**——侵入小、可审计 | 先做 **B**：可立刻演示闭环；把 A 记为演进路线 |
| 就地改 or 副本 | 就地改会破坏原脚本可复现性、多用户并发不安全 | **生成修改版副本** `output/nl_scripts/build_hydraulic_nl.py`，原脚本只读 |
| 保留证据 | 需要让人/评委看到"AI 改了哪里" | 输出 **diff（-旧行/+新行）** 到 JSON 记录 |
| 参数耦合 | 液压缸各段 Z 坐标互相依赖（缸长变了，缸头/杆都要联动）；"缸长"不能像直径那样单行替换 | 本版 SCHEMA 只放**独立尺寸（直径类）**；耦合参数列为**难点**与下一步 |
| 直径→半径 | NL 说"外径100"，脚本常量是半径 | 解析层做 直径/2 → 半径，JSON 里保留换算说明 |

## 3. 编码与调试实录（真实发生的问题）

### 3.1 复用了先前 nl_to_3d.py 调试中踩过的坑
- 教训①：调用 Blender 脚本参数必须用 `--` 分隔，否则脚本 argparse 拿不到参数（`build_housing` 只带 `--out` 时曾静默失败）；
- 教训②：Blender 不加 `--python-exit-code 1` 时，脚本异常**仍返回 0**，会掩盖失败；
- 处置：`nl_modify_script.py` 的 run_blender 一律 `... --python-exit-code 1 --python <script> -- ...`，失败打印日志尾部。

### 3.2 本次新增代码
- `scripts/nl_modify_script.py`：SCHEMA(中文词→常量) → parse_changes(正则提取尺寸) → modify_script(读原脚本→行级常量替换→写副本+diff) → run_blender(修改版建模) → render_glb(渲染)。
- 关键词示例：缸筒外径/缸径→`BARREL_R`、法兰直径→`CAP_R`、活塞杆直径/杆径→`ROD_R`、油口直径→`PORT_R`（均直径转半径）。

## 4. 验证记录（真实运行结果）

输入：`液压缸 缸筒外径100 法兰直径130 活塞杆直径36`
输出（AI 解析）：
```json
"changes": { "BARREL_R": 50.0, "CAP_R": 65.0, "ROD_R": 18.0 }
```
脚本 diff（修改版副本）：
```
- BARREL_R = 40.0      →  + BARREL_R = 50.0
- CAP_R    = 55.0      →  + CAP_R    = 65.0
- ROD_R    = 14.0      →  + ROD_R    = 18.0
```
Blender 运行修改版 → `output/nl_modified_hydraulic.glb` + 3 视角 PNG（已验证生成，尺寸按新直径建模）。

产物：`output/nl_modify_record.json`（完整记录）、`output/nl_scripts/build_hydraulic_nl.py`（修改版脚本）。

## 5. 局限与下一步（AI 判定）

1. **耦合参数**（缸长/各段高度/孔位置）：需把建模几何重构为"参数相对布局"（自底向上推导各段 Z），才能支持一句话改长度；
2. **对象覆盖面**：目前仅液压缸；壳体、包装盒可照同模式扩展（包装盒已走 CLI 参数化路径）；
3. **真实 LLM 替换**：当前解析为离线规则(demo)；接入 LLM 时把 parse_changes 换成模型输出即可，结构不变；
4. **安全**：修改版脚本在受控副本上运行，原脚本不被改写——避免"AI 改坏原工程"。

该引擎证明"一句话 → 真实脚本修改 → Blender 出 3D"在程序设计层面可落地；
AI 的参与体现在：需求拆解、方案选型、SCHEMA 设计、踩坑规避、验证与文档化。
